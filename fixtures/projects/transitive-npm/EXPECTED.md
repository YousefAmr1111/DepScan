## Why `overrides` is in package.json

```json
"overrides": { "ansi-regex": "4.1.0" }
```

`strip-ansi@5.2.0` asks for `ansi-regex@^4.1.0`. npm resolves that range to the newest
4.x, which is now `4.1.1` — the patched release — so without the override the fixture
drifts to a clean tree as soon as the registry moves. The override pins the vulnerable
version so this ground truth stays stable.

This was not a theoretical concern: two earlier candidates were discarded during this
prompt for exactly this reason.

| Candidate                                             | What npm resolved          | Result                             |
| ----------------------------------------------------- | -------------------------- | ---------------------------------- |
| `superagent@3.8.3` → `form-data@^2.3.1`               | `form-data@2.5.6` (fixed)  | 46 packages, 0 findings — rejected |
| `strip-ansi@5.2.0` → `ansi-regex@^4.1.0`, no override | `ansi-regex@4.1.1` (fixed) | 0 findings — rejected              |

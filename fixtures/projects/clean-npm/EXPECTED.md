# EXPECTED — clean-npm

Ground truth for the `clean-npm` fixture. A scan of this project must produce **zero
vulnerabilities**. Any finding here is a false positive and must be treated as a bug.

## How this was verified

Every package in the lockfile was queried against the OSV.dev API
(`POST https://api.osv.dev/v1/query`, `ecosystem: "npm"`) on **2026-10-08**. All twelve
packages returned `vulns: []`. Nothing here is unverified.

- `package-lock.json` — lockfile v3, generated by `npm install --package-lock-only`.
  No `node_modules` is installed and none is needed.

## Notes for the engine

- The nested `ms@2.1.2` exists because `debug@4.3.4` depends on the exact version
  `ms@2.1.2`, not a range, while the project itself pins `ms@2.1.3`. npm keeps both. A scan
  that reports one entry per package _name_ instead of per `name@version` will be wrong
  here (11 rows, not 12).
- This fixture is the regression guard for over-reporting: a "clean" scan that invents a
  finding is as much a bug as a scan that misses one.

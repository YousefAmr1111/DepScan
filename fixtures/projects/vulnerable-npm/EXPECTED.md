# EXPECTED — vulnerable-npm

Ground truth for the `vulnerable-npm` fixture. Three old direct dependencies, each with
known advisories. A scan must find **10 distinct vulnerabilities** across the three
packages.

## How this was verified

Every package in the lockfile was queried against the OSV.dev API
(`POST https://api.osv.dev/v1/query`, `ecosystem: "npm"`) on **2026-10-08**, and every
advisory record was then fetched individually from `GET https://api.osv.dev/v1/vulns/{id}`
to read its ranges and severity. Nothing here is unverified. Severities below are the
GitHub ratings OSV returns in `database_specific.severity`; mapping them onto the report
enum (`critical`/`high`/`medium`/`low`) is an open engine decision, and `MODERATE` is
expected to become `medium`.

The counts below were re-derived from the recorded responses in
`packages/core/fixtures/osv/` after P05b fixed over-merging. See
`reports/P05b-report.md`: the previous count of 8 was wrong because two of lodash's
advisories name **two** CVE ids each, and each CVE id is its own vulnerability.

## Files

- `package.json` — `lodash@4.17.20`, `minimist@1.2.5`, `qs@5.2.0`, pinned exactly.
- `package-lock.json` — lockfile v3, generated by `npm install --package-lock-only`.
  No `node_modules` is installed and none is needed.

## Notes for the engine

- **Deduplication is still required.** OSV returns 10 records for these three packages and
  there are 10 distinct CVEs, but no two records are interchangeable: every record must end
  up attached to the findings for the CVEs it names, and to exactly those.
- **A CVE id never becomes an alias of another finding.** CVE-2026-4800 is its own row, so it
  is absent from the aliases of CVE-2021-23337 even though the same advisories name both.
- **The report `id` field only accepts `CVE-*` or `GHSA-*`.** Every advisory here satisfies
  that, but the PyPI fixture (see `../python-basic/EXPECTED.md`) also returns `PYSEC-*`
  records, which the current schema pattern rejects. The engine must choose an id the schema
  accepts.
- All findings here are `isDirect: true`, so `risk.flags.isDirect` must be `true` and
  `risk.flags.hasFix` must be `true` for every one of them.
